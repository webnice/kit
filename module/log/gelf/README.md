# module/log/gelf

`module/log/gelf` — клиент протокола GELF (Graylog Extended Log Format) версии 1.1 для отправки сообщений журнала на сервер Graylog по сети.

Пакет кодирует сообщения в JSON и доставляет их по протоколам UDP (с разбивкой на чанки и необязательным сжатием gzip/zlib), TCP или TLS (с автоматическим восстановлением соединения). Клиент реализует `io.Writer`, что позволяет направить в Graylog вывод стандартного пакета `log`.

## Возможности

- отправка сообщений GELF версии 1.1 в формате JSON;
- транспорт UDP — протокол по умолчанию: постоянное соединение, разбивка сообщения на чанки с магическим заголовком, идентификатором сообщения и порядковым номером;
- транспорты TCP и TLS: отправка сообщения целиком с нулевым байтом-разделителем, автоматическое переподключение при обрыве связи с настраиваемой политикой попыток;
- сжатие сообщений алгоритмами gzip и zlib для транспорта UDP, уровень сжатия настраивается;
- уровни важности сообщений — константы syslog severity (`SeverityEmergency` … `SeverityDebug`);
- стандартное поле `facility` и дополнительные поля сообщения с автоматическим префиксом `_` по спецификации GELF;
- реализация `io.Writer`: перенаправление вывода `log.SetOutput` / `io.MultiWriter` в Graylog;
- тайм-аут установки соединения, конфигурация TLS;
- справочник ошибок на `github.com/webnice/dic` с уникальными кодами.

## Формат адреса сервера

```
[proto://]host:port
```

| Часть адреса | Значение |
|---|---|
| `proto` | Сетевой протокол: `udp` (значение по умолчанию), `tcp`, `tls` или `tcp+tls`. Регистр не имеет значения. |
| `host` | Имя хоста или IP-адрес сервера Graylog. |
| `port` | Порт подключения, обязательный, число от 1 до 65535. |

Примеры: `graylog:12201`, `udp://graylog:12201`, `tcp://192.168.1.14:12201`, `tls://graylog.example.com:12201`.

## Состав пакета

| Файл | Назначение |
|---|---|
| `client.go` | Клиент отправки сообщений: разбор адреса, опции, кодирование, сжатие, выбор транспорта, `io.Writer`. |
| `message.go` | Структура сообщения GELF и его JSON-кодирование. |
| `udp.go` | Клиент протокола UDP: постоянное соединение, разбивка сообщения на чанки. |
| `tcp.go` | Клиенты протоколов TCP и TLS, менеджер соединения с автоматическим переподключением. |
| `types.go` | Интерфейсы `Client`, `ProtocolClient`, тип сжатия `Compression`, константы severity, опции. |
| `errors.go` | Справочник ошибок пакета. |

## Основные сущности

- `Client` — интерфейс клиента отправки сообщений: `Send(msg *Message)`, `SendData(data []byte)`, `Close()`, `io.Writer`.
- `ProtocolClient` — интерфейс клиента сетевого протокола: `SendData(data []byte)`, `Close()`. Реализации — UDP и TCP клиенты, доступные также напрямую через `NewUdp` и `NewTcp`.
- `Message` — сообщение GELF: стандартные поля и карта `Keys` дополнительных полей.
- `Compression` — тип сжатия сообщений: `CompressionNone`, `CompressionGzip` или `CompressionZlib` (только для UDP).
- `SeverityEmergency` … `SeverityDebug` — уровни важности сообщений, syslog severity 0–7.
- `Option` — функция настройки клиента: `WithCompressLevel`, `WithChunkSize`, `WithDialTimeout`, `WithReconnect`, `WithTLSConfig`.
- `DefaultChunkSize` — размер полезных данных одного чанка UDP по умолчанию, 1420 байт.
- `DefaultMaxReconnect`, `DefaultReconnectDelay` — политика переподключения по умолчанию: 3 попытки с паузой 1 секунда.
- `Errors()` — справочник ошибок пакета.

## Использование

```go
package main

import (
	"fmt"

	"github.com/webnice/kit/v5/module/log/gelf"
)

func main() {
	var (
		cli gelf.Client
		msg *gelf.Message
		err error
	)

	// Создание клиента для сервера Graylog по протоколу UDP со сжатием gzip.
	if cli, err = gelf.New("udp://127.0.0.1:12201", gelf.CompressionGzip); err != nil {
		fmt.Println(err)
		return
	}
	defer func() { _ = cli.Close() }()
	// Формирование и отправка сообщения.
	msg = gelf.NewMessage("backend-01", "Краткий текст сообщения", gelf.SeverityInfo)
	msg.Full = "Полный текст сообщения"
	msg.Facility = "application"
	msg.Keys["request_id"] = "b3f1c2"
	if err = cli.Send(msg); err != nil {
		fmt.Println(err)
		return
	}
}
```

Отправка по протоколу TLS с настройкой переподключения и тайм-аута соединения:

```go
cli, err := gelf.New("tls://graylog.example.com:12201", gelf.CompressionNone,
	gelf.WithTLSConfig(tlsConfig),
	gelf.WithReconnect(5, time.Second),
	gelf.WithDialTimeout(10*time.Second))
```

Если `WithTLSConfig` не указана, используется конфигурация TLS по умолчанию с именем сервера из адреса и минимальной версией TLS 1.2.

Перенаправление вывода стандартного журнала в Graylog через `io.Writer`:

```go
cli, err := gelf.New("udp://127.0.0.1:12201", gelf.CompressionNone)
if err != nil {
	// ...
}
log.SetOutput(io.MultiWriter(os.Stderr, cli))
```

Каждый вызов `Write` отправляет сообщение с уровнем `SeverityInfo`: первая строка текста становится кратким текстом сообщения, весь текст — полным; поля `host` и `facility` заполняются именем хоста и именем исполняемого файла.

## Сообщение GELF

Структура `Message` соответствует спецификации GELF 1.1:

| Поле | JSON-ключ | Назначение |
|---|---|---|
| `Version` | `version` | Версия формата сообщения, всегда `1.1`. |
| `Host` | `host` | Имя хоста отправителя сообщения. |
| `Short` | `short_message` | Краткий текст сообщения. |
| `Full` | `full_message` | Полный текст сообщения, опускается при пустом значении. |
| `Time` | `timestamp` | Временная метка UNIX с микросекундной точностью. |
| `Level` | `level` | Уровень важности сообщения, syslog severity. |
| `Facility` | `facility` | Категория (подсистема) отправителя, опускается при пустом значении. |
| `Keys` | `_<имя>` | Дополнительные поля; при кодировании имена получают префикс `_`, уже существующий префикс не дублируется. |

Конструктор `NewMessage(host, short, level)` заполняет версию формата, текущую временную метку и создаёт пустую карту дополнительных полей.

## Протокол UDP

Соединение с сервером постоянное: устанавливается при создании клиента и закрывается методом `Close`. Сообщение разбивается на чанки размером `chunkSize` байт полезных данных (по умолчанию `DefaultChunkSize`). Каждая датаграмма содержит заголовок из 12 байт:

| Смещение | Размер | Содержимое |
|---:|---:|---|
| 0 | 2 | Магический заголовок чанка `0x1e 0x0f`. |
| 2 | 8 | Идентификатор сообщения, случайные байты, общие для всех чанков сообщения. |
| 10 | 1 | Порядковый номер чанка, начиная с 0. |
| 11 | 1 | Общее количество чанков сообщения. |

Максимальное количество чанков одного сообщения — 128. Сообщение, не помещающееся в 128 чанков, отклоняется с ошибкой `MessageTooLarge` до начала отправки.

При сжатии `CompressionGzip` или `CompressionZlib` сообщение целиком сжимается до разбивки на чанки; сервер Graylog определяет тип сжатия по магическим байтам автоматически. Уровень сжатия задаётся опцией `WithCompressLevel` (константы пакета `compress/flate`).

## Протоколы TCP и TLS

Сообщение отправляется целиком без разбивки; в конец добавляется нулевой байт-разделитель сообщений. Сжатие сообщений не поддерживается: попытка создать клиента TCP или TLS со сжатием завершается ошибкой `CompressionNotSupported`.

Соединение устанавливается при создании клиента. Менеджер соединения `tcpConnMng` потокобезопасно сериализует запись сообщений и восстанавливает соединение: если соединение отсутствует или запись завершилась ошибкой, выполняется переподключение с повторной отправкой данных. Политика переподключения задаётся опцией `WithReconnect(attempts, delay)`: до `attempts` попыток с паузой `delay` между ними (по умолчанию 3 попытки с паузой 1 секунда). Тайм-аут установки соединения задаётся опцией `WithDialTimeout`.

Протокол TLS (схемы адреса `tls://` и `tcp+tls://`) работает поверх TCP с шифрованием; конфигурация TLS задаётся опцией `WithTLSConfig`.

## Ошибки

Все ошибки пакета описаны справочником `Errors()` и сравниваются методом `Is` библиотеки `github.com/webnice/dic`:

| Код | Ошибка | Причина |
|---:|---|---|
| 001 | `UnknownProtocol` | Не известный протокол в адресе сервера, поддерживаются `udp`, `tcp`, `tls`. |
| 002 | `InvalidAddress` | Адрес сервера не является корректным: не указан порт или порт не является числом в допустимом диапазоне. |
| 003 | `UnknownCompression` | Не известный тип сжатия сообщений. |
| 004 | `CompressionNotSupported` | Сжатие сообщений не поддерживается протоколами TCP и TLS. |
| 005 | `MessageTooLarge` | Размер сообщения превышает максимально допустимый для отправки по UDP. |
| 006 | `NotConnected` | Соединение с сервером не установлено. |

Ошибки сетевых операций (установка соединения, запись, TLS-рукопожатие) возвращаются без обёртки.

Пример проверки ошибки:

```go
if err = cli.Send(msg); err != nil {
	if gelf.Errors().MessageTooLarge.Is(err) {
		// Сообщение слишком большое для отправки по UDP.
	}
}
```

## Тестирование

Тесты покрывают инструкции пакета, включая сквозные сценарии отправки сообщений через локальные UDP-, TCP- и TLS-серверы (TLS-сервер поднимается управляемым сервером библиотеки `github.com/webnice/net` с самоподписанным сертификатом), разбивку на чанки, сжатие gzip и zlib, переподключение TCP при обрыве связи, политику попыток переподключения, `io.Writer` и граничные случаи размера сообщений. Непокрытыми остаются только ветки защитной обработки ошибок, недостижимые на поддерживаемых платформах: сбой `crypto/rand`, ошибки записи `bytes.Buffer` в поток сжатия и частичная запись UDP-датаграммы.

Проверки: `go test -race ./module/log/gelf/` и `go vet ./module/log/gelf/` должны проходить.
